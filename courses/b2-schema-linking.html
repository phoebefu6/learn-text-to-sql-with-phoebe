Part 1 · covers the 4,602-query error analysis

What schema linking is - and why it is failure #1 8 min live

Schema linking is the pre-processing step that maps the phrases in a question onto the actual objects in your database: "Pro plan" → customers.plan, "cancelled" → subscriptions.cancel_date. When that mapping is missing, the model does what language models do - it invents a plausible-sounding object. The database calls those inventions ghosts: columns and tables that simply do not exist.

LiveThe 81.2% stat, unpacked4 min▶

A published error analysis dissected 4,602 failed text-to-SQL queries and asked: what actually went wrong? The answer was lopsided: 81.2% were schema errors - the model picked the wrong column, or mapped the question's meaning onto the wrong objects entirely (the paper's two buckets: wrong column selection and semantic misinterpretation).

  • Not syntax. Modern LLMs write grammatical SQL almost every time. The SQL parses fine - it just points at the wrong things.
  • Two flavors of schema error. Invent an object that does not exist (loud - the database refuses), or pick a real object that means the wrong thing (silent - it runs). Tonight kills the first flavor.
  • Why it dominates: the question is written in business language and the schema is written in engineer language. Nothing in a raw CREATE TABLE dump bridges the two.
Self-studySchema vocabulary vs business vocabulary2 min read▶

Look at the ghosts in the diagram: subscription_tier, users, churn. None are random. Each is the business word from the question, dressed up as a database object. "Churn" is a real concept at Daybreak - it just is not a table; it is a rule about cancel_date. That gap between the words your org speaks and the names your schema uses is where most text-to-SQL failures live, and you will meet it again in b4 (docs carry the vocabulary) and b5 (a semantic layer defines it).

Quick exercise for your own warehouse: say ten common stakeholder questions out loud and note which nouns have an obvious column home and which are pure business vocabulary. The second list is a preview of your failure log.

Part 2 · covers ACM CSUR taxonomy + Genie guidance

How real systems link schemas 8 min live

You cannot paste a 1,000-column enterprise schema into a prompt and call it linking. Real systems treat schema linking as an explicit stage: retrieve the tables and columns relevant to this question - by string matching, by embedding similarity, or both - and put only those in front of the model.

DaybreakGPT rung 1 - the schema-linked prompt for Q2 You are a SQL expert. Given these RELEVANT tables (selected by the schema linker for this question), write one SQLite query. Use ONLY the tables and columns listed. Return only SQL. CREATE TABLE customers (customer_id INTEGER PRIMARY KEY, name TEXT, city TEXT, country TEXT, signup_date TEXT, plan TEXT); -- column note: plan holds the tier name, e.g. 'Pro' Question: How many customers are on the Pro plan?
LiveRetrieval beats dumping - and the field made it a named stage4 min▶

The peer-reviewed technique taxonomies (ACM Computing Surveys and the survey line this course follows) treat schema linking as its own pre-processing stage, and the best-known named methods all implement it explicitly: C3 ranks and filters candidate tables and columns before generation, DIN-SQL makes schema linking the first module of its decomposed pipeline, and CHESS runs dedicated retrieval over schema plus context before its generator ever sees the question.

  • String retrieval: match question tokens against table/column names and synonyms. Cheap, surprisingly strong on well-named schemas.
  • Embedding retrieval: embed the question and every schema element; take the nearest. Catches "city" → customers.city even when phrasing drifts.
  • The tradeoff: retrieve too little and the right column is missing (guaranteed failure); retrieve too much and you are back to strategy A. Production systems tune k on a golden set - which you own since b1.
Real world

Databricks' own Genie numbers make the case. Their published curation guidance caps a Genie space at 30 Unity Catalog tables but recommends 5 or fewer, and their worked example shows a fresh, uncurated space scoring 8 of 15 benchmark questions - rising to 15 of 15 after curators trimmed scope and added metadata. Vendor-reported figures on a vendor benchmark, so hold them loosely - but notice the direction: the fix was less context, better chosen. That is schema linking as product policy.

Self-studyWhy fixing a layer exposes the next one2 min read▶

This is the course's recurring plot twist, so meet it properly the first time. Q4's naive failure was a ghost column - loud, honest, obviously broken. Give the model the real schema and it now writes fluent SQL over real objects... that ignores the business rule that revenue means delivered orders only. The error did not disappear; it descended a layer - from names (schema) to meaning (semantics) - and went quiet on the way down.

That is why this track is a ladder, not a single trick: each lever fixes its own layer and hands the survivors to the next. Names → patterns (b3) → vocabulary (b4) → definitions (b5) → recovery (b6). If your accuracy bar ever jumps and your remaining failures all go silent, you have not finished - you have found the next session.

See the ground truth yourself The whole fight is over what tables actually exist. Ask SQLite directly - this is the list the naive model never saw, and the reason its ghosts died loudly.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · A published error analysis dissected 4,602 failed text-to-SQL queries. What did it find?

The distribution is lopsided: 81.2% schema errors (wrong column selection plus semantic misinterpretation). Modern LLMs write grammatical SQL - it just points at the wrong things. That is why schema linking is lever #1.

2 · Genie allows 30 tables per space but Databricks recommends 5 or fewer. Why would less context beat more?

The point is precision, not cost: each extra table offers plausible-but-wrong columns to grab. Retrieval of a small relevant subset is schema linking; prompting everything is the naive baseline wearing a bigger prompt.

3 · After tonight, Q4 (total revenue) runs without error but silently includes cancelled orders. What does that tell you?

The SQL uses only real, correctly linked objects - the mapping is perfect. What is missing is a definition no schema carries. Fixing one layer exposes the next, and the exposed failures are the silent kind.
